# 情感故事号（story-account）

面向**抖音 30-40 岁女性受众**的情感故事口播生产线。它的目标不是「生成一条视频」，
而是**把「像 AI 写的」这件事挡在交付之前**。

用一个比喻说清楚它和通用口播包（`spoken-video`）的关系：

> 通用口播包是一间设备齐全的**演播室**——信号、选题、写稿、配音、字幕、渲染、
> 质检、发布资料一应俱全。
> 本包是针对情感故事赛道的**整套装修方案**：沿用同样的水电管线（阶段产物、
> 配音字幕、竖屏渲染、ffprobe 质检、独立审片），但把焊点全换成了这条赛道
> 真正会出事的地方。

---

## 为什么需要单独一个包

情感故事赛道有三个别的赛道没有的失效模式：

| 失效模式 | 其他赛道的后果 | 情感故事的后果 |
|---|---|---|
| AI 味（句长均匀、爱升华、无对白） | 稍显生硬 | **第 8 秒就被划走**，完播率断崖 |
| 编造具体细节 | 表述不准 | **冒充真实经历**，账号信任一次性崩塌 |
| 结尾升华成道理 | 略显说教 | 情绪被消解，观众不转发也不留言 |

所以本包把这三件事做成了**确定性检查**，而不是提示词里的一句「请注意」。

---

## 素材由 agent 主动找

素材和选题都不该让人填表——日更节奏下，人每天去翻评论、翻问答是最容易断的一环，
断在这里后面全停摆。所以这两步都由 agent 主动产出：

| 环节 | agent 做什么 | 人做什么 |
|---|---|---|
| 素材采集 | 检索并筛选「有具体场景 + 一句原话」的真实素材，带来源地址 | 勾选入库 |
| 故事选题 | 基于素材池与账号定位自行判断，给出**排序后**的候选，每条带推荐理由与依据强度 | 点「用这个选题」 |

两条硬规矩：

1. **没有来源地址的素材直接丢弃**。没有出处等于编造，而编造是本赛道最贵的风险。
2. **采集结果不自动入库**。入库只能走 `adoptHarvest`，由人勾选。自动入库等于让
   模型产出的内容不经任何人过目就流进成片。

采集不到不是失败：agent 如实返回空结果并说明缺什么、该去哪找，比交一份编好的
素材有用得多。

> 子 agent 的联网能力来自父会话的 `standard` preset（`tool-web`，search + fetch
> 均启用）。这是本仓库首次让子 agent 主动联网找素材——`spoken-video` 走的是自家
> HTTP 抓热榜，且明确禁止抓取网络素材。**实跑验证尚未做**，且 `web_search` 需要
> `DEEPSEEK_API_KEY`。

## 三道闸门

### 1. 反塑料感闸门（写稿阶段，硬拦）

`story-account-antiplastic.mjs` 把「人味」拆成六项可测量指标：

| 检查 | 判据 | 处理 |
|---|---|---|
| 套路词 | 重生 / 穿越 / 霸总 / 豪门 / 车祸失忆 / 绝症 | **硬拦** |
| 升华结尾 | 我终于明白 / 后来我才懂 / 这就是人生 / 愿你… | **硬拦** |
| 人物对白 | 正文 ≥120 字却没有任何直接引语 | **硬拦** |
| 句长节奏 | 标准差 < 4.5 且短句占比 < 12% | **硬拦**（AI 指纹） |
| 场面具体度 | ≥200 字却没有任何时间/地点/物件锚点 | **硬拦** |
| AI 口癖 | 某种意义上 / 五味杂陈 / 空气中弥漫着… 累计 ≥3 处 | **硬拦** |

单处口癖、对白带书面语、锚点偏少等**只给建议不拦截**——「这句不够口语」是判断，
不是事实，让机器一票否决会误杀好稿子。

### 2. 技术闸门（成片阶段）

`ffprobe` 客观读数：**1080×1920 / 30fps / 有音轨 / 有字幕 / 音画时长差 ≤ 2 秒**。

### 3. 独立审片闸门（成片阶段）

独立子会话说人话：以「30-40 岁女性深夜刷抖音」的身份看抽帧，只回答
**前 3 秒会不会被划走、哪一帧会让她划走**。

两个闸门是「**与**」不是「或」：技术不过，审片说破天也不通过；审片发现
blocker/major，分数再高也不通过。`mergeReview` 是唯一可信的判定点。

> 为什么还要跑一次反塑料感：成片阶段允许「导入稿件」跳过写稿页，那条路径
> 不经过写稿闸门。质检页是最后一次机会。

## 阶段与产物

```
定位 → 素材 → 选题 → 稿件 → 配音 → 字幕 → 成片 → 质检 → 发布资料
```

| 阶段 | 谁能写 | 关键约束 |
|---|---|---|
| 选题 topic | 人 / AI | `scenario` 与 `keyLine` 必填，缺一即丢弃 |
| 稿件 script | 人 / AI | 落库前跑反塑料感，硬拦即拒 |
| 配音 / 字幕 | 受控任务 | 竖屏字幕单行 16 字 |
| 成片 / 质检 / 发布资料 | **只能受控任务** | 浏览器桥无法伪造 |

## 声音方案（音色 + 语气 + 语速打包）

这条赛道的账号人设靠声音辨识：**一个声音跑到底**，中途换音色会被老观众立刻
听出来。所以这里不开放上传参考音频，也不把「音色 / 模型 / 语气 / 语速」四件事
摊给用户填表，而是打包成一张张声音卡片。

| 方案 | 声音 | 模型 | 语气 | 语速 |
|---|---|---|---|---|
| 温柔女声 | 冰糖 | 预置音色 | 温柔舒缓，适合情感共鸣 | 0.92 |
| 知性女声 | 茉莉 | 预置音色 | 清晰沉稳，语速平缓克制 | 0.94 |
| 沉稳男声 | 白桦 | 预置音色 | 沉稳有力，适合观点表达 | 0.94 |
| 评书旁白 | 音色描述 | 音色设计 | 描述里写明年迈、沙哑、语速缓慢 | 0.92 |
| 纪录片旁白 | 音色描述 | 音色设计 | 描述里写明低沉醇厚、平缓克制 | 0.90 |

每张卡片带 **▶ 试听**：走本机媒体桥接的试合成端点真去云端合一段，回传音频
就地播放。试听失败（Key 没额度、描述写得不对）当场看得见，不必等到成片。

配音走桥接任务协议：`POST /api/v1/tts/jobs` → 轮询 → `/audio-files/` 下载，
产物落进专属工作区的 `media/voiceovers/`。**不要**自己拼一个合成端点——媒体
服务没有别的入口，路径写错只会得到一个看不出问题的 404。

## 本地验证

```bash
cd lifafa-workbench-main
npm run pack:link                      # 建立 vendor 运行期链接
npm run check                          # 语法检查（含本包全部模块）
npm test                               # 链接 + 语法 + profile 冒烟 + 全部单测
node --test lwb/packs/story-account/test/*.test.mjs
```

生命周期（安装 / 重载 / 启用 / 卸载 / 重装）由 `test/lifecycle.test.mjs` 覆盖，
用的是 `pack-manager.mjs` 的导出函数而不是 CLI——要断言的正是「装好 ≠ 启用」
这个两步语义，以及重复安装不会在注册表里留下两条记录。

渲染链的真实验证（需要 ffmpeg 与 Remotion 依赖）不在单测里跑，用一次性脚本：

```bash
# 合成一段静音配音 → 搭 Remotion 工程 → 真渲染 → ffprobe → 技术质检
node lwb/packs/story-account/test/render-smoke.mjs
```

实测输出：1080×1920 / 30fps / h264+aac / 20.16 秒，技术质检通过。

## 已知边界

- **不含内容安排（定时任务）**：前期日更需要人守评论区，自动发布会在最该
  互动的阶段把账号做死。这是刻意的产品决定，不是没做完。
- **字幕是节拍对齐，不是 ASR 时间戳**：字幕严格跟着画面节拍走（一拍拍一
  条字幕），因此不会出现「画面换了三句、字幕还停在第二条」；但每条字幕在
  拍内的位置仍按字数比例估算，标记为 `aligned: false`。发布前请听一遍。
- **不向平台直发**：只准备发布资料。需要投递请加载「发布与账号管理」能力包。
- **素材是唯一事实来源**：模型编不出的细节必须写进 `unsupportedDetails`，
  这条约束靠提示词 + 落库校验双重保证，但不做语义级事实核查——那需要检索。
- **封面大字本地叠字**：中文交给生图模型会糊字，所以封面底图可以由模型生成，
  大字一律由 ffmpeg drawtext 在本地叠加。
- **素材采集尚未实跑验证**：agent 联网找素材这条链静态上成立（子 agent 继承父
  会话 preset 拿到 `tool-web`），但没有真跑过一次 harvest 去确认它确实调用了
  `web_search`；且 `web_search` 需要 `DEEPSEEK_API_KEY`。首次使用前建议在界面上
  实跑一轮采集确认。
