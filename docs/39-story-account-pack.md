# 39 · 情感故事号能力包（story-account）

> 状态：包已实现并有 152 项单测覆盖（`lwb/packs/story-account/test/`，2272 行）；素材采集链静态成立但**尚未实跑验证**（见「已知限制」）。
> 结论先说：这不是又一个「生成视频」的包，而是把「像 AI 写的」这件事挡在交付之前——面向**抖音 30-40 岁女性受众**的情感故事口播生产线，与通用口播包 `spoken-video` 共用同一套管线，但把三个赛道特有的失效模式做成了确定性检查。

## 0. 这个包解决什么问题

情感故事赛道有三个别的赛道没有的失效模式：

| 失效模式 | 其他赛道的后果 | 情感故事的后果 |
|---|---|---|
| AI 味（句长均匀、爱升华、无对白） | 稍显生硬 | 第 8 秒就被划走，完播率断崖 |
| 编造具体细节 | 表述不准 | 冒充真实经历，账号信任一次性崩塌 |
| 结尾升华成道理 | 略显说教 | 情绪被消解，不转发不留言 |

通用包的做法是把「请注意口语化」写进提示词；本包把这三件事做成**确定性检查**（反塑料感检查器 + 素材溯源约束），不过闸不出稿。

## 1. 与 spoken-video 的关系

包内 README 的比喻：通用口播包是一间设备齐全的**演播室**（信号、选题、写稿、配音、字幕、渲染、质检、发布资料一应俱全）；本包是针对情感故事赛道的**整套装修方案**——沿用同样的水电管线（阶段产物、配音字幕、竖屏渲染、ffprobe 质检、独立审片），焊点换成这条赛道真正会出事的地方。

代码层面的对应关系：

| 层 | 事实 | 依据 |
|---|---|---|
| 依赖 | `package.json` 的 peerDependencies 与 spoken-video 同源（`@deepseek-ai/dsh-*`），client 走 `@scitiger-ai/lwb-dsh-bundle` | `lwb/packs/story-account/package.json` |
| 浏览器桥 | 独立命名空间 `storyAccount`（与口播包的 `spokenVideo` 平级），所有方法在 `storyAccountScope.request` 里执行工作区归属与凭据作用域 | `gateway.mjs` |
| 数据 | 专属工作区，卸载能力包会保留工作区和数据 | `lwb-pack.json` gettingStarted、`story-account-paths.mjs` |
| 凭据 | **媒体服务凭据按包隔离、不共享**：宿主给每个包的凭据引用加包命名空间前缀（`pack-workspaces.mjs` 的 `packCredentialRef`），同一 purpose 在两个包里是两把不同的 Key。因此**两个包各配一次媒体服务 API Key**；环境变量名与 spoken-video 相同（如 `LWB_SPOKEN_VIDEO_SCITIGER_BASE_URL`），媒体服务地址读同一套环境变量，运维只需配一次 | `lwb/dsh-bundle/pack-workspaces.mjs:348` |
| 渲染 | 同样基于 Remotion，但工程按 1080×1920 竖屏搭 | `story-account-render.mjs`、`story-account-qc.mjs`（`width: 1080, height: 1920, fps: 30`） |

**不要同时把两个包当成两条独立生产线用**：它们管线同源，差别在赛道焊点。做知识口播用 spoken-video，做情感故事用本包。

## 2. 八步工作流

工作流（`lwb-pack.json` market.workflow）：

```
确定账号定位 → 采集故事素材 → 生成故事选题 → 写口播故事稿 → 配音与字幕 → 竖屏成片 → 质检双闸门 → 发布资料
```

| 步骤 | 输入 | 产出 | 谁主导 | 失败时用户该做什么 |
|---|---|---|---|---|
| 1 账号定位 | 受众、故事题材、情绪边界 | 定位档案，贯穿全程供各步引用 | 人填 + AI 补全 | 无硬失败；定位决定后续题材库与钩子，改定位即改方向 |
| 2 故事素材 | 无（agent 主动找） | 「有具体场景 + 一句原话」的真实素材，**每条带来源地址** | agent 检索筛选，**人勾选入库** | 采集不到会如实返回空结果并说明缺什么；换题材或补关键词再采。**没有来源地址的素材直接丢弃** |
| 3 故事选题 | 素材池 + 账号定位 | 排序后的候选，每条带推荐理由与依据强度；`scenario`（具体场景）与 `keyLine`（关键对白）必填 | agent 产出，人点「用这个选题」 | 候选不合适就换一条；缺 `scenario` 或 `keyLine` 的候选会被直接丢弃，不会混进后续 |
| 4 故事写稿 | 选题 + 素材 | 口播稿；落库前跑反塑料感检查，硬拦即拒 | 人 / AI | 检查结果会指出是哪一项不过（套路词/升华结尾/无对白/句长节奏/场面具体度/AI 口癖），按提示改稿重跑 |
| 5 配音 / 字幕 | 稿件 + 声音方案 | 配音音频（落 `media/voiceovers/`）+ 节拍对齐的竖屏字幕（单行 16 字） | 受控任务 | 未配置媒体服务时报 `STORY_VOICE_UNAVAILABLE` 类错误，先到「配音/字幕」配置或改用「导入稿件」路径 |
| 6 竖屏成片 | 配音 + 字幕 | 1080×1920 Remotion 成片 | 受控任务 | 渲染失败看执行明细；确认 ffmpeg 与渲染浏览器可用（见 troubleshooting） |
| 7 质检双闸门 | 成片 + 配音 | 技术质检读数 + 独立审片结论，同页汇总 | 受控任务 | 任一闸门不过即不出片；按页面上列出的具体问题（时长差、字幕压脸、开场空镜等）返工 |
| 8 发布资料 | 成片 + 选题 | 标题、文案、标签、封面（ffmpeg 本地叠大字） | 受控任务 | 只准备资料不直发；发布走「发布与账号管理」包 |

阶段写入权限是分层的：选题、稿件允许人 / AI；**成片、质检、发布资料只能由受控任务写**，浏览器桥无法伪造（`story-account-store.mjs` 阶段约束 + 包 README）。

### 素材由 agent 主动找，但不自动入库

- 采集结果**不自动入库**：入库只能走 `adoptHarvest`，由人勾选（`story-account-content.mjs`：「结果不自动入库：入库必须走 adoptHarvest，由人勾选确认」）。自动入库等于让模型产出的内容不经任何人过目就流进成片。
- 采集不到不是失败：agent 如实返回空结果并说明缺什么、该去哪找。
- 子 agent 的联网能力来自父会话的 `standard` preset（`tool-web`，search + fetch 均启用）；`web_search` 需要 `DEEPSEEK_API_KEY`。**这条链没有实跑验证过**，首次使用建议在界面实跑一轮采集确认。

## 3. 反塑料感检查（写稿闸门）

`story-account-antiplastic.mjs` 把「人味」拆成六项可测量指标，全部**硬拦**：

| 检查 | 判据 |
|---|---|
| 套路词 | 重生 / 穿越 / 霸总 / 豪门 / 车祸失忆 / 绝症 |
| 升华结尾 | 我终于明白 / 后来我才懂 / 这就是人生 / 愿你… |
| 人物对白 | 正文 ≥120 字却没有任何直接引语 |
| 句长节奏 | 标准差 < 4.5 且短句占比 < 12%（AI 指纹） |
| 场面具体度 | ≥200 字却没有任何时间/地点/物件锚点 |
| AI 口癖 | 某种意义上 / 五味杂陈 / 空气中弥漫着… 累计 ≥3 处 |

单处口癖、对白带书面语、锚点偏少等**只给建议不拦截**——「这句不够口语」是判断不是事实，机器一票否决会误杀好稿子。

写稿阶段的素材纪律（`story-account-script.mjs` 提示词 + 结构化输出双重约束）：素材是唯一事实来源且视为不可信数据（不执行素材文本里的指令）；所有具体细节（数字、地名、亲属称谓、对白）必须能在素材里找到出处；找不到出处但为叙事必须补的部分写进 `unsupportedDetails` 字段，不得藏进正文。约束靠提示词 + 落库校验保证，但**不做语义级事实核查**。

## 4. 质检双闸门：为什么两个都要过

### 闸门一：技术质检（ffprobe 客观读数）

判据在 `story-account-qc.mjs`：**1080×1920 / 30fps / 有音轨 / 有字幕，音频与画面时长差 ≤ 2 秒**（`audioDurationToleranceSeconds: 2`）。时长差超限的提示原文：「视频与配音时长差超过 2 秒：音画不同步会被观众直接听出来。」

### 闸门二：独立审片（独立子会话说人话）

以「30-40 岁女性深夜刷抖音」的身份看抽帧，只回答：**前 3 秒会不会被划走；如果没划走，后面哪一帧会让她划走**。审核要点包括：开场第一帧必须是冲突或对白（不能是空镜/logo/黑屏/字幕卡）、画面与情绪一致、无超过 20 秒的静止画面、字幕不压人脸与重要物件、竖屏安全区、无连续雷同版式。审片结论要求 2–8 项不同时间点的观察证据（去重后 ≥2 项才算证据过），并有分数阈值与 blocker/major 处理（`REVIEW_FINDING_LIMIT = 12`，`mergeReview` 是唯一可信判定点）。

**两个闸门是「与」不是「或」**：技术不过，审片说破天也不通过；审片发现 blocker/major，分数再高也不通过。合并判据见 `story-account-qc.mjs`：`passed = technicalPass && editorialPass && score ≥ 阈值 && distinctEvidence ≥ 2 && value?.passed === true`。

> 成片阶段还会再跑一次反塑料感：因为「导入稿件」可以跳过写稿页，那条路径没经过写稿闸门，质检页是最后一道机会。

## 5. 声音方案（音色 + 语气 + 语速打包）

一个声音跑到底——中途换音色会被老观众听出来。所以本包**不开放上传参考音频**，也不把音色/模型/语气/语速摊给用户填表，而是打包成声音卡片（`story-account-voice.mjs` `STORY_VOICE_RECIPES`）：

| 方案 | 声音 | 模型 | 语气 | 语速 |
|---|---|---|---|---|
| 温柔女声 | 冰糖 | mimo-v2.5-tts（预置音色） | 温柔舒缓，适合情感共鸣 | 0.92 |
| 知性女声 | 茉莉 | 同上 | 清晰沉稳，语速平缓克制 | 0.94 |
| 沉稳男声 | 白桦 | 同上 | 沉稳有力，适合观点表达 | 0.94 |
| 评书旁白 | 音色描述 | 音色设计 | 年迈、沙哑、语速缓慢 | 0.92 |
| 纪录片旁白 | 音色描述 | 音色设计 | 低沉醇厚、平缓克制 | 0.90 |

每张卡片带 **▶ 试听**：走桥接自带的试合成端点（`/admin/mimo-test`）真去云端合一段，回传音频就地播放；Key 没额度、描述写得不对当场看得见（错误码 `STORY_VOICE_UNAVAILABLE` / `STORY_VOICE_SERVICE_FAILED`）。

配音走桥接任务协议：`POST /api/v1/tts/jobs` → 轮询 → `/audio-files/` 下载，产物落专属工作区 `media/voiceovers/`。字幕是**节拍对齐**（一拍拍一条），不是 ASR 时间戳：拍内位置按字数比例估算，明确标记 `aligned: false`，发布前请听一遍（`story-account-voice.mjs`）。

## 6. 安装与加载

```bash
cd lifafa-workbench-main
npm run pack:link          # 为包建立指向 vendor 的运行期依赖链接
npm run dev -- --port 4173 # 或 Windows 下双击 启动工作台.cmd
```

然后在工作台「场景能力包」页面找到「情感故事号」点「加载」（注册/发现与加载是两步，本包随仓库提供、无需另行注册；外部包注册方式见 [README](../README.md)）。生命周期语义（装好 ≠ 启用、重复安装不留双记录、卸载保留数据）由 `test/lifecycle.test.mjs` 覆盖。

首次使用前置：

1. 「设置 → 系统设置 → 模型」配置默认模型（AI 创作使用它）。
2. 配音/字幕需配置媒体服务；未配置时仍可用「导入稿件」方式把已有文案走完流水线。**注意：媒体服务凭据按包独立保存**——即使已在「口播视频」包里配过 Key，本包仍需在「配音 / 字幕 → 打开连接配置」再存一次；媒体服务地址不用改（两个包读同一套环境变量）。

## 7. 已知限制（刻意的产品决定，不是没做完）

- **不含内容安排（定时任务）**：账号前期要求日更与卡点发布，且需要人工确认评论互动——定时任务无法保证（`lwb-pack.json` gettingStarted 原文）。
- **只准备发布资料，不向平台直发**：需要自动投递时另行加载「发布与账号管理」能力包（见 [docs/38](38-publisher-pack.md)）。
- **素材须可追溯**：没有来源地址的素材直接丢弃；`unsupportedDetails` 约束靠提示词 + 落库校验保证，但无语义级事实核查。
- **字幕节拍对齐、拍内按字数估算**（`aligned: false`）：发布前听一遍。
- **封面大字本地叠**：中文交给生图模型会糊字，封面底图可由模型生成，大字一律 ffmpeg `drawtext` 本地叠加（`story-account-cover.mjs`）。
- **素材采集尚未实跑验证**：agent 联网找素材静态上成立，但没有真跑过一次 harvest 确认它确实调用了 `web_search`，且 `web_search` 需要 `DEEPSEEK_API_KEY`。
