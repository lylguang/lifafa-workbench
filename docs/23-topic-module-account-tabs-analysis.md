## 0. 总判断

**方向成立，且与项目既定原则高度一致**：账号是选题的一等公民（17/22 文档脉络）、抽屉交互已有三处先例（信号抽屉、账号抽屉、来源抽屉）、「左配置右任务」比「左录入右单任务视图」更贴近任务型工作台的本质。四点需要修正或明确边界后采纳：

1. **表单应该全 Tab 统一**，而不是只有通用 Tab 简化（见 2.1）；
2. **「忽略信号」≠「本次不用」**，复用信号抽屉会引入语义偏差，需要划清（见 2.3）；
3. **「默认选最适合」用 prompt 排序实现**，不引入新评分机制（见 2.4）；
4. **「具体信号」勾选列表退役**，但要想清楚是否保留单条信号驱动的入口（见 2.5）。

## 1. 现状盘点

### 1.1 页面结构（`client.js:875-1027` TopicsPage）

- 左栏表单：账号下拉（含「不使用账号定位」选项）+ 选题标题 + 切入角度 + 信号源徽章多选 + **具体信号勾选列表**（945 条活跃信号平铺滚动，体验最差的一块）+ 提交按钮；
- 右栏单任务视图：三态切换（待确认 / 运行中步骤流 + DSH 实时事件 / 完成态候选列表），下方挂「最近生成记录」（点击切换 `genId`）与「已确认选题」两个区块；
- 提交锁定：`running` 时左栏禁用，天然单并发。

### 1.2 后端接缝（`spoken-video-topic.mjs` / `spoken-video-content-store.mjs`）

| 事实 | 对本次重设计的意义 |
|---|---|
| `parseTopicInput` 已接受 `accountId / angle / sourceIds / signalIds`，四项至少一项 | 简化表单（仅 angle + sourceIds）**零后端改动**即可提交 |
| `assembleMaterial` 只取 `state === 'active'` 的信号组装层 | 「忽略」操作天然把信号移出选题输入——信号抽屉的忽略按钮在这里直接产生选题侧效果 |
| `SOURCE_LIMIT = 20`，本地 17 个来源 | 初始全选不会被上限拦截 |
| 无全局 `MATERIAL_POOL_LIMIT` | 选题编排先为每个已选渠道确认当天最新批次，再将每个批次的全部有效信号交给 DSH；不再从全库按评分截取 Top-N |
| 候选默认选第一个是前端 `record.candidates[0]` 写死；`buildTopicPrompt` 未要求排序 | 「选最适合」的落点在 prompt 规则，不在前端（见 2.4） |
| 生成记录已含 `summary / steps(detail) / dsh.events / materialMode / elapsedMs / account 快照` | 执行摘要抽屉的素材**全部现成**，后端零新增 |
| `listSignals` 支持 `sourceIds + platform` 过滤 | 来源抽屉按来源列出信号已是现成能力（`SignalDrawerBody`） |

### 1.3 真实数据佐证

- `.lwb/spoken-video/topic-generations.json` 4 条历史记录：`title` 与 `angle` **全部为 null**，全部走「选信号源」模式——四输入里标题/角度两项实际使用率极低，简化表单有数据支撑；
- `signals.json`：945 条信号、全部 active、17 来源（含 `ai-daily-import`）；
- `topic-profile.json`：5 个账号、已设默认账号。

### 1.4 与文档 21 的衔接

21 已删除信号卡「送入选题」，并定下「选题页具体信号勾选列表是信号→选题唯一通道」。本次重设计将**修订该结论**：勾选列表退役，新通道 = 来源卡片（整源参与）+ 抽屉内排除/忽略单条信号。这是合理演进——945 条滚动勾选本就不可用。

## 2. 逐点判断

### 2.1 Tab 化 ✅ 成立，但表单应全 Tab 统一（修正点）

用户表述是「**在这个（通用）Tab 下**，不再是四输入……」，隐含账号 Tab 保留旧四输入。建议改为：**所有 Tab 共用同一套简化表单（角度 + 来源卡片），Tab 只决定注入哪个账号快照**。理由：

- 账号 Tab 注入了更强的约束（定位/受众/方向/边界全进 prompt），表单反而应该更简，不该比通用 Tab 更复杂；
- 数据证明标题/角度输入实际使用率极低（1.3），为账号 Tab 保留四输入没有收益；
- 单一表单 = 单一提交流、单一测试面，符合零兼容原则下"概念越少越好"的惯例。

Tab 排布：`[账号 A] [账号 B] … [通用(无账号定位)]`。通用 Tab 固定放最后；默认账号可加角标提示。每个 Tab 维护独立表单状态（角度 + 来源选择），切换不互相污染；若嫌实现繁琐，共享一份表单状态也可接受（决策点 A/B）。

### 2.2 来源卡片 + 默认全选 ✅ 成立

复用信号板已建立的卡片视觉语言（[20] 文档的 `sv-board-card` 体系：glyph、状态徽章、hover 提升），按账号定位 tone 改为橙色系 accent。初始全选只是便利初值；勾选明确决定哪些渠道的当天最新批次参与本轮，卡片上显示「已选 n」与全选/清空快捷操作。

**AI 内容日报的粒度（决策点 H）**：信号板已把 `ai-daily-import` 拆成 5 张平台卡展示，但后端 `sourceIds` 语义只有来源级（选它 = 5 平台全进）。选题来源卡若也拆平台，需要 `assembleMaterial` 支持 `source + platform` 过滤（中等改动，且与「双链路分治」视觉一致）；若不拆，整源一张卡（零改动）。

### 2.3 复用信号抽屉：忽略 ≠ 本次不用 ⚠ 必须划清（修正点）

`SignalDrawerBody` 的「忽略」是**全局状态变更**（`setSignalState → ignored`）：该信号从此退出所有选题的素材池与信号板活跃统计，直到手动恢复。如果用户在选题抽屉里点「忽略」的真实意图是「这条本次不参与」，全局忽略就是**语义过冲**。

两种处置（决策点 C）：

| 选项 | 内容 | 改动面 | 评价 |
|---|---|---|---|
| **C1（推荐）** | 抽屉内信号行加「本次参与」勾选（默认勾选），取消 = 本次排除，仅影响当前提交（前端收集 `excludeSignalIds` 传给后端）；「忽略」按钮保留为显式全局动作 | `parseTopicInput` / `assembleMaterial` / gateway 增一个可选参数；前端状态 | 语义诚实，与零兼容原则下"概念要准"一致 |
| C2 | 直接复用现有「忽略」，不加临时排除；提示文案写明「忽略后不再参与后续生成，可在信号模块恢复」 | 零改动 | 省事但把全局决策塞进临时场景，用户容易误伤 |

注意 `excludeSignalIds` 的取舍：不能靠前端把"留下的信号"枚举成 `signalIds` 传入（`SIGNAL_LIMIT = 30`，单来源活跃信号可能超限，如 AI 日报单平台约 190 条），所以排除语义必须由后端承接。

### 2.4 默认选「最适合」✅ 成立，用 prompt 排序落地（修正点）

不新增评分模型、不做后端重打分（LWB 不维护第二套模型运行时，01/17 红线）。落地方式：

1. `buildTopicPrompt` 规则追加一条：「候选按推荐程度从高到低排列，第一个是你认为最该做的」；
2. 前端默认选中第一个候选不变，但卡片加「推荐」徽章，文案从「默认选中第 1 个 · 可改选」改为「已默认选中推荐候选 · 可改选」；
3. 排序责任归 DSH（它本来就掌握账号约束与素材全貌），选择权仍在人——与 17 文档「选择权始终在人」的纪律一致。

### 2.5 「具体信号」勾选列表退役 ⚠ 留一个开放问题

列表退役后，「我就要围绕某一条具体信号做选题」的场景只剩一条路：在抽屉里把同来源的其他信号全部排除/忽略——太重。三个选项（决策点 D）：

- **D1**：不保留单条入口（最简）；单条驱动的场景由「角度」输入兜底（把信号标题写进角度）；
- **D2**：抽屉内信号卡加「以此为核心」动作，把该信号 id 加入 `signalIds`（后端已支持，前端收集）；
- **D3**：左栏保留折叠的「高级 · 指定具体信号」区。

倾向 **D1 起步**，有真实诉求再升 D2。

### 2.6 执行摘要按钮 + 抽屉 ✅ 成立

右栏不再为摘要单独留空态占位。任务卡上挂「执行摘要」按钮，抽屉内容全部来自现有生成记录字段：输入回显（账号快照 / 角度 / 来源）+ 素材统计（mode + 命中数）+ 四步流程（含 detail）+ DSH 事件流 + 耗时。后端零新增。

### 2.7 候选抽屉 ✅ 成立

任务完成后点任务卡（或卡上「查看候选」）弹候选抽屉：候选卡展示 `title / angle / videoForm / contentCore / whyNow / 依据信号数`，单选切换，底部「确认选题 · 建项目」与「重新生成」。确认链路（建项目 → 信号依据 → topic artifact）**完全不变**。

### 2.8 右栏任务列表化 ✅ 成立（顺带整合）

现状右栏「单任务视图 + 最近生成记录」本就是同一份数据的两种呈现，重设计后合并为**统一任务列表**：

- 每张任务卡：摘要（`record.summary`）+ 状态徽章（运行中 / N 个候选 / 失败）+ 账号标签（来自哪个 Tab，读 `record.account?.name`，无则「通用」）+ 相对时间；
- 动作：「执行摘要」常显；「查看候选」仅完成态；运行中卡片显示步骤进度摘要行；
- 并发维持单任务：`running` 时左栏禁用提交（现状即此，决策点 E 默认维持）；
- 「已确认选题」区块保留在列表下方或移入流水线视图（小决策，随视觉稿定）。

### 2.9 布局与美化 ✅ 成立

左配置右任务的分栏沿用 `sv-split` 体系，视觉语言全面对齐 [20] 文档已建立的规则（卡片圆角/描边/ hover、glyph 徽标、徽章色系、相对时间），选题模块 accent 用 `lwb-pack.json` 既定的 orange。层次靠「区块标题 + 卡片 + 徽章」三层表达，不引入新视觉体系。可先在 Ardot 出视觉稿确认再落代码（决策点 F，[22] 同款问题）。

### 6.2 关键实现决策

- **渠道选择 = 最新批次范围**：前端将当前勾选渠道传入；若调用方没有指定渠道，编排层才以所有启用渠道为范围。每个范围内的渠道都必须有当天有效批次，缺失时先补采；`platforms` 仅在日报部分勾选时传（全选或全不传都走整源语义）。
- **本次排除 vs 全局忽略**：抽屉内「本次参与」勾选写 `form.excluded`（仅本次提交传 `excludeSignalIds`），与既有「忽略」（`setSignalState`，跨选题全局）并存且语义分离；说明条明示两者区别。
- **推荐候选**：`buildTopicPrompt` 规则要求 DSH 按推荐度降序输出，前端 `candidates[0]` 即推荐项，候选抽屉第一张卡挂「推荐」徽章并默认选中；不新增评分机制。
- **确认链路不变**：候选确认仍走 `create → commit(signals) × N → commit(topic, account snapshot)`；`signals` 依据改为确认时按候选引用的 `signalIds` 调 `listSignals({ids, state:'active'})` 精确取信号（不再依赖页面常驻的全量 signals 状态，也不受 500 条时间序 limit 截断）。

## 8. 缺陷诊断与修复（2026-09-06）：候选/摘要抽屉无法滚动（已按方案 A 修复）

用户报告：选题完成后的候选弹窗无法滚动查看完整信息。

### 8.1 根因

`.sv-drawer` 在 `productCss` 里有**两处定义，后者覆盖前者**：

| 位置 | 定义 | 用途 |
|---|---|---|
| 基础段（行 14） | `position:fixed; …; overflow:auto; padding:22px;` | 初版抽屉：**整体滚动** |
| v2.2 信号页改造段（行 259） | `display:flex; flex-direction:column; overflow:hidden;` | 信号抽屉重构：**头/工具行固定 + 内部滚动** |

同特异性、后者在级联中获胜 → 所有 `.sv-drawer` 都变成 `flex 列 + overflow:hidden`。这套模式的**契约**是：抽屉的直接子节点必须自己当滚动容器，即 `.sv-drawer-scroll { min-height:0; flex:1; overflow:auto; }`（行 276）。

全站 8 处 `aside.sv-drawer` 按此契约分两类：

| 抽屉 | 直接子容器 | 是否可滚 |
|---|---|---|
| 信号抽屉（信号页 + 选题页复用，行 859/1336） | `sv-drawer-head` + **`sv-drawer-scroll`** | ✅ |
| 写稿页 3 抽屉（行 1646/1668/1697） | `sv-drawer-head` + **`sv-drawer-scroll`** | ✅ |
| **候选抽屉（行 1294）** | `sv-drawer-head` + **`sv-drawer-list`** + `sv-tp-drawer-foot` | ❌ |
| **执行摘要抽屉（行 1265）** | `sv-drawer-head` + **`sv-drawer-list`** | ❌ |
| **账号编辑抽屉（行 985）** | `form.sv-drawer-list`（头也在内） | ❌（表单短，未暴露） |

`sv-drawer-list` 只有 `display:grid; gap:8px`（行 14），没有任何 `flex:1 / min-height:0 / overflow` 属性——作为 `overflow:hidden` flex 列的直接子项，内容超出即被**裁切且无滚动条**。候选抽屉 5 张卡（标题+形态+内容核心+whyNow）轻易超过视口，所以用户在这里撞上；摘要抽屉内容更长（回显+统计+步骤+DSH 事件）同样中招；账号抽屉因表单短暂未暴露，但属同一缺陷。

这是我在 9/5 重写 TopicsPage 时**沿用了旧账号抽屉的 `sv-drawer-list` 直挂结构**、没有对齐信号抽屉 `sv-drawer-scroll` 契约造成的——v2.2 改造时旧结构侥幸存活（当时 `.sv-drawer` 还是 `overflow:auto`），改造后契约变了，新写的抽屉踩中。

附带效应：`.sv-tp-drawer-foot` 的 `position:sticky; bottom:0` 在不可滚的 flex 列里失效（sticky 需要滚动祖先），底部按钮区随内容一起被裁切——所以用户不仅滚不动列表，连「确认选题」按钮都可能看不见。

### 8.2 修复方案（待拍板，暂不动手）

**方案 A（推荐，1 行 CSS）**：让直挂的 `sv-drawer-list` 继承滚动契约——

```css
.sv-drawer > .sv-drawer-list { min-height:0; flex:1; overflow:auto; }
```

- 子选择器只命中「直接子级」：候选/摘要抽屉修复；信号与写稿抽屉的 `sv-drawer-list` 是 `sv-drawer-scroll` 的孙级，不受影响；
- `flex:1` 同时让候选抽屉的 `sv-tp-drawer-foot`（flex:none 兄弟项）自然钉底，sticky 失效问题一并消解；
- 账号抽屉同被修复（副作用：抽屉头在 form 内，会随内容滚走——可接受，或后续把头移出 form）；
- 风险：三处抽屉同时变化，需亮/暗双主题回归一遍。

**方案 B（结构对齐）**：把候选/摘要抽屉改为 `sv-drawer-head + sv-drawer-scroll(内装 sv-drawer-list) + sv-tp-drawer-foot` 三段结构，与信号抽屉完全同款。改动面大一点（JSX 两处），但结构语义最干净，foot 钉底不依赖 flex 兄弟项行为。

倾向 A 起步（一行修三处），若验收发现账号抽屉头部滚走的观感不可接受，再对账号抽屉单独做 B。


## 9. 候选池改造（2026-09-06）

单选“确认选题”把一个候选批次错误建模成只能落成一个项目的终态：任务虽产出多个可写选题，写稿页却只能消费唯一的 `confirmedProjectId`。现改为候选级、可逆的待写稿队列。

- DSH 仍按推荐度降序返回候选；第一个候选在任务完成时由服务端自动建成 `topic` 项目并加入待写稿，避免“推荐”只是一次弹窗内的视觉预选。
- 每个候选持久化 `id + selection(state/projectId/时间/来源)`；候选抽屉改为多选 checkbox 语义，可分别加入其他候选，不关闭原任务，也不必重新生成。
- 写稿页继续只读项目，但 `listWritableTopics` 现在只返回 `topicSelected=true` 的项目。候选撤回时不删除项目和信号/选题工件，只将其移出写稿队列；重新加入复用同一项目，不会重复建项目。
- 已有已保存稿件或运行中的写稿任务不可直接撤回，服务端拒绝该请求，避免把已开始的生产链路悄然隐藏。此类项目后续应通过显式归档处理。
- 历史的 `confirmedProjectId/confirmedTitle` 记录在首次读取时迁移为相应候选的 `selected` 状态与项目关联，现存可写稿项目不丢失。

## 10. 任务并发修订（2026-09-07）
