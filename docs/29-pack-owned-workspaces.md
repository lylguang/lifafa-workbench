# 29 能力包专属工作区

实施日期：2026-09-15。专属工作区已合入 main，基于 DSH 0.1.6。模型配置已修正为复用 DSH 默认选择和认证，能力包不再提供独立 AI 模型连接表单。

## 产品行为

每个工作台实例内，每个能力包有一个专属工作区。首次加载自动创建，之后按包身份复用。业务页面无需新建普通工作区或对话，切换普通对话不改变能力包数据。暂不提供绑定普通工作区的入口。

| 操作 | 注册关系 | 业务文件 | 连接配置与凭据 | DSH 审计日志 |
|---|---|---|---|---|
| 卸载能力包 | 保留 | 保留 | 保留 | 保留并隐藏 |
| 清空业务数据 | 保留原状态 | 移至可恢复副本，重建空目录 | 保留 | 保留并隐藏 |
| 解除工作区注册 | 解除活动绑定，保留归属历史 | 保留 | 保留 | 保留并隐藏 |
| 再次加载 | 恢复登记 | 使用同一目录 | 继续使用该包配置 | 继续隐藏 |

维护入口在能力包详情中，必须先卸载、等待所有任务停止。清空与解除注册是两个独立按钮，各自确认。清空包含账号、信号、项目、音视频文件、任务和内容安排；不会自动导入旧普通工作区的数据。清空返回可恢复目录，并非不可恢复的安全擦除。

CLI `pack:remove` 删除的是市场中的包源登记，与上述工作区注册关系不同；它同样不删除业务文件。

## 工作区和会话

`LwbPackWorkspaces` 使用 `<DSH_HOME>/profiles/lwb/pack-state`：

```text
ownership.json
workspaces/<pack-id>/data/...
retained/<pack-id>-<reset-id>/...
```

2026-09-16：口播包使用上述 `data/` 布局，已移除旧隐藏子目录和跨工作区索引回退。完整约定见[运行数据目录](31-runtime-data-layout.md)。

工作区由 LWB 持久化登记，不加入 DSH 普通 Workspace Registry。DSH `ui-workspace` 的 `watchNavigation()` 会自动选择已登记的普通工作区；把能力包写入同一个登记表会干扰普通对话初始状态。内部执行通过 DSH 原生 Agent 的 `meta.cwd` 指定目录即可，无需注册到普通工作区选择器。

业务读写使用 `{ packId, workspaceId, workspacePath, generation, status }` 上下文，不构造伪 Agent。AI 执行时按需创建内部根 Agent，复用 DSH 原生预设和子代理；一个专属工作区可有多个内部执行会话。

根会话 id 在发布前写入归属索引。LWB 普通列表、搜索、归档和计数按归属 id 与 cwd 过滤根会话；子代理沿用已有 `origin: subagent` 过滤。归属信息尚未读取时不展示会话，避免闪现。解除注册和清空后仍保留历史归属，不改写 DSH Session 格式。

## 能力包接入契约

Host 声明 `lwbPackServices` 依赖，通过 `getLwbPackScope(ctx, manifest)` 或 `ctx.lwbPackServices.forPack(manifest.id)` 获取宿主已创建的作用域。

| 接口 | 使用方式 |
|---|---|
| `context()` | 取得唯一数据上下文 |
| `request(operation)` | 跟踪一次完整 RPC，后端决定数据目录 |
| `background(promise)` | 跟踪已启动的完整后台任务，必须包含最后一次写入与队列衍生任务 |
| `onStop(disposer)` | 登记计时器等停止回调 |
| `signal` / `fetch` | 包级取消信号、自动合并取消信号的 HTTP 请求 |
| `withAgent(operation, signal?)` | 按需创建、使用、释放包内 DSH Agent |
| `assertAgent(agent)` | 工具调用只能来自该包目录 |
| `credentials` | 把包自身业务接口的凭据操作限制到包命名空间；DSH 模型认证由原生适配器处理 |
| `settingsNamespace(name)` | 分配包级设置名称；通过包自身的 `ctx.settings.register()` 注册，确保卸载释放 schema |

核心只向浏览器业务页传 `packId`、公开 pack/menu 和导航回调。数据 RPC 不接收用于选址的 `agentId`/`cwd`。业务 host 保留真实 Agent 入参兼容以供测试和内部工具复用，生产浏览器入口统一使用宿主上下文。

动态插入的样式必须在创建时明确设置 `data-plugin` 为自身 package name。DSH 模块加载会认领未标记样式；不标记可能导致卸载一个包时误删宿主样式。

## 模型、任务与隔离

内部 Agent 通过 `agentDefaultModel.currentSelection()` 读取 DSH 默认服务商、模型及推理强度，认证、图片输入等模型能力由 DSH 已有配置决定。用户只需在 DSH 设置中配置，无需在能力包详情重复填写。每个新任务读取最新默认选择，已开始的任务保持启动时的选择，不读取浏览器当前普通对话的局部覆盖。

能力包不创建模型路由、不检查专用模型 key，也不修改 DSH 模型配置。缺少默认选择时提示前往 DSH 设置；服务商不可用、认证失败、模型能力不足等由 DSH 原生执行返回。调度的就绪检查只判断默认选择是否存在，不把“存在默认选择”当作联网或认证成功。

口播的 TTS、ASR 和封面生图目前直接调用供应商接口，这些业务连接继续使用独立命名空间；包内配音和发布可使用同一个供应商 key。它们与 DSH 的对话模型认证是不同用途，配置不相互覆盖。凭据引用使用符合 DSH shell identifier 规则的长度前缀，避免包/用途边界碰撞。

旧实现创建的 `lwb-pack-<id>` 模型路由和模型凭据不会被本次修复自动删除或迁移，新执行不再自动选择它们；如果用户在 DSH 设置中显式选为默认模型，则遵循该选择。修复不清空用户配置、业务数据或内部会话。

内部根 Agent 挂载 standard 预设，设置 workspace-write 权限后才提交任务，子代理继承原生执行边界。此功能提供宿主归属与调度隔离，不把任意第三方 JavaScript 包变成安全沙箱。

卸载先关闭请求入口，取消 HTTP、Agent、ASR WebSocket 和 ffmpeg 子进程，停止计时器，再等待前台与后台完整结算。子进程收到取消后须等 `close`，不能把 AbortError 当成已退出；Remotion 在途渲染等待 CLI 结算，避免只杀父进程留下渲染子进程。并发请求在停止期间追加的后台任务也需排空；30 秒内无法停止时返回忙碌错误，禁止维护操作，可在任务结算后重新卸载。DSH Loader 分组显式记录动态条目，移除时等待异步释放，避免“已卸载但仍在运行”。

口播信号采集与内容安排只访问专属目录，不扫描旧普通工作区索引。新加载时启用的公开信号源可能自动采集，所以清空后的信号池可能再次出现新数据，这是新采集，不是旧数据恢复。
