# 快速开始：从安装到第一条口播视频

本指南面向首次使用工作台的本机单用户。工作台可以持续接入独立场景能力包；下面以随仓库提供的第一个包“口播视频内容创作”为例。

## 环境要求（装机前置清单）

动手安装前先核对下表。缺项不会在安装时全部暴露，往往在后面的环节才以报错出现，先补前置比排查报错更快。

| 前置 | 要求 | 不满足时的现象 |
|---|---|---|
| Node.js | `^22.19.0 || >=24.0.0`，建议 22 LTS 最新补丁版本 | 版本过低时安装即失败或 JSON import 报错 |
| Git | 终端可直接执行 `git` | `npm run setup` 无法克隆/检出上游 |
| Corepack | 适配当前 Node 的版本，可用 `npm install -g corepack` 安装 | `setup` 依赖 `corepack pnpm` 构建上游 |
| C/C++ 编译环境 | Node 原生依赖的编译工具链（macOS 用 `xcode-select --install`） | `npm ci` 或上游构建阶段编译原生模块失败 |
| FFmpeg | 在**启动工作台的同一终端**里 `ffmpeg -version`、`ffprobe -version` 均可执行 | 配音、视频合成与转码链路不可用 |
| Python 3（含 pip） | 解释器具备 `opencv-python`、`numpy`、`Pillow` 三个库 | 白板手绘动画（独立的白板包，以及口播视频里的白板画面）依赖它们。系统 Python 已具备时会被直接复用；缺失时可在「渲染」页点「准备环境」建隔离 `.venv`，但国内网络下安装 opencv-python 可能拖几十分钟，建议提前给系统 Python 装好三件套 |
| Windows 符号链接权限 | 开启「开发者模式」（设置 → 隐私和安全性 → 开发者选项），或用管理员身份运行终端 | npm/pnpm 安装依赖和运行期建链会创建符号链接，未开启时报 `EPERM` / `operation not permitted` |
| 中文字体 | 视频含中文时，运行主机有可用的中文字体 | 成片出现方框或缺字 |

### 全新克隆的正确顺序

`npm run dev` 只负责启动工作台，**不下载也不构建上游**。全新克隆必须按顺序执行：

```bash
git clone https://github.com/lylguang/lifafa-workbench.git
cd lifafa-workbench
npm ci            # 1. 按锁文件安装根目录依赖
npm run setup     # 2. 克隆并构建上游 DSH（耗时最长）
npm run dev -- --port 4173   # 3. 启动
```

跳过前两步直接启动，会报 `Missing vendored DSH checkout`，或在测试/加载能力包时报 `ERR_MODULE_NOT_FOUND`——上游运行期链接尚未建立。

### GitHub 访问超时的替代做法（镜像）

`setup` 需要从 GitHub 克隆上游仓库。网络超时或限速时，不要修改 `UPSTREAM.lock.json` 来“解决”网络问题。可行的变通做法：先用任意可用的 GitHub 镜像把上游仓库克隆到 `vendor/deepseek-harness`（镜像需包含 `lwb/UPSTREAM.lock.json` 指定的 commit），再执行 `npm run setup`；脚本检测到该目录已存在会跳过克隆，只做 fetch、检出锁定 commit 并构建。建议后续由后端同学给 `npm run setup` 增加 GitHub 镜像 fallback 参数，此处先以文档说明变通步骤。

## 1. 安装工作台

先按上面的[环境要求](#环境要求装机前置清单)核对 Node.js、Git、Corepack 和本机 C/C++ 编译环境，再执行：

```bash
git clone https://github.com/lylguang/lifafa-workbench.git
cd lifafa-workbench
npm ci
npm run setup
npm run dev -- --port 4173
```

根目录依赖使用 npm 锁文件安装。`setup` 会克隆、检出并构建 [UPSTREAM.lock.json](../lwb/UPSTREAM.lock.json) 指定的 DSH，在上游目录使用其 pnpm 版本；不要在根目录另行初始化 pnpm 工作区。

浏览器应打开李发发工作台，并显示“对话”“场景能力包”“设置”。首次启动没有预置业务账号、稿件或成片。若浏览器没有自动打开，用终端打印的完整带令牌 URL 访问；遇到错误先看[故障排查](troubleshooting.md)。

## 2. 配置 AI 默认模型

打开「设置 → 系统设置 → 模型」，添加或配置实际可用的服务商、API 凭据和模型，并设为默认选择。不要以页面中出现模型名称作为接口已经可用的依据。

在“对话”中选择一个普通工作区，发送简短请求验证模型连接。口播包的业务页面不需要新建普通对话或选择普通工作区，它会使用自己的专属工作区。

账号定位完善、选题、写稿和视频 Agent 复用系统默认模型。普通对话临时切换的模型不一定改变这个默认值。视频制作需要模型能够执行工具；独立审片还需要支持图片输入，应选择服务商实际提供这些能力的模型。

## 3. 加载第一个场景能力包

打开「场景能力包」，找到「口播视频内容创作」，点击「加载」。左侧应出现账号定位、信号、选题等八个入口。

仓库内的包自动进入目录，不需要再运行 `pack:install`。外部包才需要先在本机注册源目录，再到页面加载。已启用的包会在下次启动时恢复，卸载只停止运行并移除菜单，保留业务文件与配置。

内置信号源默认启用，会按采集规则访问公开来源。可在“信号”的来源管理中停用不需要的来源；采集状态和错误可以在页面查看。

## 4. 配置媒体制作依赖

只测试选题和写稿，可以稍后再完成这一节。

### 本地工具

安装 FFmpeg，并确保启动工作台的终端能够执行：

```bash
ffmpeg -version
ffprobe -version
```

macOS 如已安装 Homebrew，可运行 `brew install ffmpeg`。其他系统请按 [FFmpeg 下载说明](https://ffmpeg.org/download.html)安装对应构建。

在项目根目录下载 Remotion 所需的渲染浏览器：

```bash
npx --no-install remotion browser ensure
```

也可以显式使用本机 Chrome/Chromium 的**可执行文件**。例如 macOS 的 Google Chrome：

```bash
export LWB_REMOTION_BROWSER_EXECUTABLE="/Applications/Google Chrome.app/Contents/MacOS/Google Chrome"
npm run dev -- --port 4173
```

在已有进程启动后设置环境变量不会影响该进程，需要重启工作台。中文视频还需要本机可用的中文字体；出现方框或缺字时先检查字体环境。

### 服务连接

| 用途 | 配置入口 | 注意事项 |
|---|---|---|
| AI 创作与审片 | 设置 → 系统设置 → 模型 | 使用系统默认模型和该服务商的凭据 |
| 配音和字幕识别 | 配音 / 字幕 → 连接配置 | 选择百炼或 SciTiger，保存媒体服务 API Key |
| 封面生图 | 发布 → 封面生图 | 配置生图服务；它与媒体连接是不同的配置入口 |

同一个供应商的 Key 可能可用于多个入口，但配置不会自动互相覆盖。请确认对应模型权限、区域/工作空间及额度；这些请求可能产生供应商费用。本项目不提供免费的模型或媒体服务额度，也不要求必须使用 SciTiger。

## 5. 完成第一条内容

1. **账号定位**：创建账号，填写受众、内容方向和表达要求；也可以使用“通用（无账号定位）”进行测试。
2. **信号**：检查采集结果。单个来源失败时，可以在选题时取消该渠道，使用其他可用来源。
3. **选题**：选择账号、参与渠道和可选的选题角度，点击生成并确认。任务会补采当天缺失的渠道；生成完成后推荐候选自动加入待写稿，其他候选可按需选择。
4. **写稿**：选择待写稿选题、篇幅和额外要求，点击「写稿」，核对确认框后启动。生成完成会保存稿件；需要调整时打开稿件编辑或润色，编辑后通过「保存并进入配音」提交。
5. **配音 / 字幕**：选择已保存稿件，核对内容、服务和音色。默认同时生成字幕，确认后开始任务。配音成功而字幕失败时，音频仍然保留，可单独重试字幕。
6. **视频 / 预览**：选择已完成配音的稿件，设置横竖屏、字幕、可选 BGM 和画面要求，确认后生成。DSH 创作 Agent 制作 Remotion 工程，主机渲染并执行技术质检、独立审片；查看执行详情定位失败阶段。
7. **发布**：检查通过质检的成片，打开发布资料，生成或修改标题、文案、标签及封面。预览、下载并自行发布到目标平台。

首次验证建议使用短篇稿件，先跑通一条完整流程。完成本节后，发布页应能查看通过质检的成片及其资料；只出现任务记录不代表制作成功。

配音页也支持直接输入文稿创建独立音频任务。要沿完整视频流程继续，请从已有项目稿件进入配音，确保音频与项目关联。

## 6. 再配置内容安排

手动流程跑通后，在「内容安排」中配置账号、执行日期/时刻、参与渠道、每轮条数和执行深度。

调度器运行在工作台服务进程中：关闭浏览器不会停止调度，退出服务则无法到点执行。错过的时刻不会自动补跑；执行记录以页面显示为准。深度到达成片或发布资料时，流程会自动推进稿件确认，请按需要选择停在写稿阶段。安排不会自动向视频平台发布。

## 7. 保存、备份与更新

默认所有产品状态都在 `lwb/local/`：账号、素材、稿件、音视频、运行记录、连接配置、凭据和原生会话。数据结构见[运行目录说明](31-runtime-data-layout.md)。

更新前停止服务并备份这个目录；自行指定过 `LWB_DSH_HOME` 或 `LWB_PACK_REGISTRY` 时，还应备份对应位置。源码更新后，在项目根目录执行 `npm ci`、`npm run setup`、`npm test`，确认依赖和上游版本匹配后再启动。不要在任务执行中更新运行时代码。

不要把包含凭据、会话内容或媒体素材的运行目录上传到 Issue 或公共仓库。卸载能力包、清空业务数据、删除包源登记分别有不同含义，操作前阅读[生命周期说明](12-capability-packs.md)。
