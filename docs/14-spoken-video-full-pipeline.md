### 1.3 缺口总结

从信号到发布资料，当前仍有两类非阻塞增强：

1. **选题规则辅助**：评分、排序与选题库管理尚未实现，优先级低于媒体链路。
2. **消费端**：发布模块只生成发布资料，不提供任何平台投递能力；这是刻意的权限边界。若日后需要「哪些视频已经发过」的台账，需要重新设计一份独立于生产状态机的发布记录（2026-09-11 简化时连同入队审计一起删除了）。

## 2. 架构决策点（动工前必须拍板）

### 决策 1：AI 能力放在哪里 —— 三层能力模型（核心决策）

LWB 的架构红线（01-architecture）：不维护第二套模型、凭据、权限运行时；12 文档明确"后续 TTS、ASR、渲染和发布适配器必须把可计费、网络与发布动作注册为 DSH 工具，并经过 DSH 权限与人工审批边界"。因此推荐三层：

- **L1 规则层（包内直做，零依赖）**：查重、口播自然度检查、SRT 参数校验、ffprobe 门禁、选题信号打分（热度/新鲜度/来源平衡）。纯函数，从 my-agent orchestrator 直接移植。永远可用。
- **L2 LLM 层（经 DSH）**：选题生成/评估、写稿、画面分镜脚本。**不**在包内私接模型 API，模型、凭据与审批始终留在 DSH 原生边界。可用姿态包括：
  - (a) 包注册领域工具，由 DSH 会话中的模型调用；适合后续 TTS、ASR、渲染等外部或可计费动作；
  - (b) 包组装上下文后跳转会话，由人发起生成并回流 artifact；
  - (c) 包从当前活体会话派生一次性结构化子代理，捕获 `outputSchema` 结果后回流候选。
  - **当前结论（2026-09-02）**：选题与写稿已采用 (c)，即 `subagents.start('spawn', { parent, prompt, outputSchema })`；AI 结果只作为人工可采用的候选。`defineTool()` + `ctx.tools.register()` 的预研已通过，保留给 P4 的外部动作。
- **L3 人工内容输入**：用户可以输入自己的稿件、配音和校对后的 SRT；这属于有效来源，不是失败兜底。视频阶段不接受人工制作说明替代成片，也不接受手工质检覆盖自动失败。

### 决策 2：媒体适配器抽象

新建 `adapters/` 层，统一接口形态（声明能力 → 提交 → 轮询 → 产物落盘 → 审计），首批四个适配器：

| 适配器 | 首选实现 | 备选/兜底 |
|---|---|---|
| TTS | 复用 my-agent 的 8020 微服务协议（提交-轮询-下载） | 云端 TTS（注册为 DSH 工具，计费走审批）；人工录音说明 |
| ASR 字幕 | 同服务 `/api/v1/subtitles/generate`（音频+文稿对齐） | 手贴/校对 SRT |
| 渲染 | DSH 创作 Agent 直接实现 Remotion；受保护组件负责音轨、画幅和确定性字幕 | 无；失败即任务失败 |
| 发布 | 发布队列导出（文件/剪贴板） | publish-manager HTTP API（如部署） |

每个可计费/网络/发布动作按 12 文档要求注册为 DSH 工具；artifact 的 `source` 字段从恒为 `manual` 扩展为记录来源（`manual` / 工具 id / 服务名）与审批回执，保持可审计。

### 决策 3：渲染方案

沿用 my-agent 的 **Remotion + 确定性字幕**架构，它是参考实现里最值钱的工程资产：

- `DeterministicSrtSubtitles.tsx` 受保护组件由 orchestrator 注入 SRT，创意部分与字幕解耦——这条纪律直接搬进 LWB；
- `remotion-best-practices` 40+ 规则作为渲染 agent/提示词的知识库；
- 渲染是本机重操作（node + headless 浏览器），作为主机侧任务执行，进度与日志进采集记录同款审计流。
- 环境结论（预研②，2026-09-01）：本机实测渲染链路全通（Node 22 managed + Remotion 4.0.463 + Chrome 无头 + ffmpeg 7.1.1）。依赖隔离建议：渲染工程按项目在工作区侧生成（`.lwb/spoken-video/projects/<id>/render/`），依赖随工程安装，不进包内 vendor——与 my-agent"创意 agent 在工作区动态建工程"的模式一致，也避免能力包膨胀。

### 决策 4：资产存储 —— 本地优先

预览与媒体资产一律落在项目目录 `.lwb/spoken-video/projects/<id>/` 下（如 `media/`、`renders/`），页面通过主机 RPC 读取本地文件引用。**不引入 OSS**（my-agent 的 OSS 签名链接方案丢弃），单机工作台没有这个需求，也避免新凭据。

### 决策 5：外部依赖清单

全链路完整可用所需的依赖及失败语义：

| 依赖 | 用途 | 缺失时行为 |
|---|---|---|
| DSH 模型（已有） | 选题、写稿、视频创作与独立审片 | 视频任务失败；能力包不另接模型密钥 |
| TTS/ASR 微服务 | 配音与字幕 | 人工录音 + 手校 SRT |
| Remotion + ffmpeg / ffprobe | 成片渲染、抽帧与技术质检 | 视频任务失败，无自动降级 |

## 3. 各模块目标形态

### 3.1 选题（P1 强化，已完成）

- 已实现：信号抽屉与「送入选题」预选、账号定位、四输入分层组装、携带来源引用的 DSH 候选生成；推荐候选自动落入待写稿，其余候选可独立加入或撤回。
- 未实现：my-agent 的规则评分/来源平衡排序、选题库管理；选题已由 AI 候选生成与人工确认覆盖主要工作流，暂不阻塞后续阶段。

### 3.2 写稿（P2–P3，已完成）

- 已实现：上游上下文、版本化编辑器与质检面板；`script_quality.js` 的查重、长度/节奏、结构与口播诊断规则；改写后的导演提示词；AI 起稿/润色的 DSH 结构化子代理；人工保存才产生 revision。
- 已实现：`approve_draft` 等价闸门。当前 revision 未经人工确认时，配音页面不展示该项目，主机也拒绝 `voiceover` 提交；稿件更新会立即使旧确认失效。
- 未实现：LLM 口播审稿与自动改写，作为非阻塞的后续增强保留。

### 3.3 配音 / 字幕（P4，已完成）

- 已实现：`spoken-video-media-host.mjs` 对接配置在环境变量中的 TTS/ASR 服务，执行提交、轮询和下载；配音与 SRT 均落在项目 `media/` 目录，并经 revision、幂等键和下游失效规则提交为自动 artifact。
- 已实现：页面提供音色、名称和语速参数、音频播放器、自动 ASR 对齐，以及按真实时间码逐条校对字幕文本；服务未配置时保留人工配音说明与人工 SRT。
- 纪律照搬：**禁止用文稿机械切分伪造时间轴**。自动字幕请求必须引用已生成的音频；人工路径由人工明确编辑并经 SRT 校验。

### 3.4 视频 / 预览（P4，完整 AI 视觉导演链路）

- 已实现：横屏 1920x1080 与竖屏 1080x1920 选择；任务创建时冻结稿件、配音、可选 SRT、方向与制作说明。
- 已实现：独立 DSH 创作会话读取任务和两份 Remotion 技能，直接编辑 `CreativeVideo.tsx`；音轨、Composition、参数和 `DeterministicSrtSubtitles.tsx` 由主机保护，禁止创作会话修改。
- 已实现：渲染前拒绝占位实现、过度简单实现、CSS 时间动画及受保护文件变更；随后使用本地固定版本 Remotion 渲染。
- 已实现：成片抽帧、主画面变化检测、音轨/尺寸/帧率/帧数/时长检查和字幕长度门禁；通过后才启动全新 DSH 审片会话。审核会话只读最终帧和报告，必须提供至少两个抽帧时间点的观察证据。
- 已实现：只有确定性技术质检与独立审片都通过才原子提交视频和 QC。任一失败都保留任务报告但不提交成片，不自动修复或切换渲染器。

### 3.5 质检（P5，已完成）

- 已实现：ffprobe 读取音视频流，检查 1080x1920、30fps、音轨、时长和字幕可用性；报告作为项目内 JSON 和不可变 `qc` artifact 保存。
- 门禁：技术问题会令 `qc.passed=false`，生成发布资料被存储层拒绝；失败的自动质检不能通过提交手工质检覆盖，必须重做视频并重新质检。

### 3.6 发布（P5 收尾 → 2026-09-10 发布包装 Agent → 2026-09-11 简化为视频货架，已完成）

- **2026-09-10 升级**：状态机新增 `packaging` 阶段。发布包装 Agent 基于冻结的账号定位、稿件、成片规格与质检结论生成标题/文案/描述/标签与横竖封面提示词；启用生图连接后自动生成 1280×720 / 720×1280 封面（百炼 BYOK 或 SciTiger 云端），封面可人工上传替换，资料可人工编辑后保存。设计与实施记录见 [25 发布模块分析](./25-publish-module-analysis.md)。
- **2026-09-11 简化（用户拍板，连根删除多余流程）**：状态机由 10 阶段收敛为 8 阶段，`approval`、`queue` 两个阶段及其闸门、`queuePackage`、ZIP 发布包导出（`exportPublishPackage`/`readExport`）全部删除。页面改为按账号陈列质检通过的成片（卡片内可直接播放，视频字节点击才拉取），点「发布」开单一抽屉：无发布资料时自动触发一次生成，已有则可编辑资料、查看并修改封面提示词后按方向单独重生（新增 `regeneratePublishCover`）、上传封面、或整体重新生成。**资料齐备（标题/文案/描述/标签）即视为可发布**，不再有任何状态切换按钮。模块依旧不向任何平台直发。完整记录见 [26 发布模块简化](./26-publish-module-simplification.md)。

### 3.7 内容安排（全自动流水线，已完成）

- 原有仅采集信号的 schedule 已由 schema 3 全自动编排器替代。安排可按账号配置周几、时刻、来源、选题角度、每轮条数、横竖屏、字幕、篇幅与音色，并选择停在选题、写稿、成片质检或发布资料。
- 成片及发布资料深度会以 `source: 'automation'` 明示记录自动确认稿件；所有后续配音仍通过与人工流程相同的后端审批闸门。
- 调度运行在主机侧，使用独立执行会话，支持工作区单飞、阶段超时、取消、错过时刻记录和重启恢复；终点最多到发布资料，不执行任何平台发布动作。

## 6. 「完整可用」的定义（验收标准）

在一台只装了 LWB 的本机上，运营者可以：

1. 信号板自动采集今日信号（已达成）；
2. 从信号一键进入选题，看到依据与 AI 候选；推荐项自动进入待写稿，并可补选其他候选；
3. 在写稿页获得 AI 起稿或至少质量检查辅助，人工确认后锁定稿件；
4. 生成（或人工准备）配音与对齐字幕，页面上可试听、可看时间轴；
5. 由 DSH Agent 直接完成 Remotion 视觉实现，渲染横屏或竖屏成片，经技术质检和独立审片后在页面内预览；
6. 自动质检通过后，成片出现在发布页的视频货架上，可直接播放；点「发布」生成或编辑标题/文案/描述/标签与横竖封面，资料齐备即可复制到平台发布；
7. 全程每一步有版本、有来源、有审计；任一上游变更，下游自动失效并提示重做。
8. 可建立内容安排，在无人值守时按授权深度运行，并在运行详情中追溯每条内容的阶段、产物与失败原因。

配音与字幕允许用户提供自己的有效产物；视频没有兜底路径。DSH、Remotion、ffmpeg 或 ffprobe 缺失时，视频任务明确失败。

|---|---|---|
