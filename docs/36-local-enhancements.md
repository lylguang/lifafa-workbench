# 本地增强说明（相对上游老傅工作台）

本仓库源自「老傅工作台」（[ScarecrowFu/dsh-laofu-workbench](https://github.com/ScarecrowFu/dsh-laofu-workbench)，最后同步提交 `5bbd0e1`，2026-09-21），并在能力包与运行层做了系统性生产增强。所有增强都位于 `lwb/`、`media-bridge/`、`ops/`、`scripts/` 与启动脚本层，**不修改锁定的 `vendor/deepseek-harness`**（上游版本见 [UPSTREAM.lock.json](../lwb/UPSTREAM.lock.json)）。

本文档逐项记录：上游痛点 → 根因 → 本仓库改动 → 实测数据。文中所有数字均来自本机生产使用的真实任务与提交记录，不是估算值。

## 一、音画同步

**上游痛点**：创作 Agent 拿不到语音时间轴，只能按稿件段落估算每个场景的秒数，误差逐章累积。实测 18 个场景里 13 个边界切在语音句子中间，画面比语音超前 2–3 个完整章节。

**根因**：上游把「字幕产物」和「视频制作」当成两条可独立进行的链路，视频侧永远在猜时间。

**改动**：
- 字幕产物成为视频制作的硬性前置条件；真实语音时间轴始终写入任务工程。
- 新增 `inspectTimelineAlignment()`：渲染前统计场景边界落在语音句子内部的比例，超过阈值即拒绝渲染，并给出修复指引。
- 创作提示词要求场景边界必须从真实时间戳推导，并回查语义对应。
- 场景边界解析统一进 `spoken-video-scene-table.mjs`（唯一真源），支持场景表优先 → 时间锚点 → 均匀抽样三档退化，退化档位写进预检报告，不再「静默退化」。
- 句级时间轴接入：桥接配音分段合成时记录句级时间轴（`splitTextSegmentsWithMeta`），SRT 生成走快路径直接使用地面真值；语音起点用 PCM 实测。

## 二、字幕对齐

**上游痛点**：字幕按字数占比估算时间，实测 20/84 条提前 0.46–0.94 秒上屏；配音页的字幕路径没有对齐守卫，云端 ASR 时间戳滞后（实测最大 15s）原样带进成片；重对齐后误差均值 7.10 秒。

**改动与实测**：
- 字幕吸附真实语音停顿，固定开口前 0.12 秒出现。
- 两条字幕路径（配音页与定时任务）都跑对齐守卫；`subtitle-align` 在占比模型误差带内的可疑结果升级到锚点校验（修掉实测漏判 0.92 放行的案例）；守卫修正输出必须过 `validateSrt`。
- 锚点密度提升使字幕尾部也被校验；重对齐后误差均值 7.10s → **1.61s**。
- cue 字数上限（横 56 / 竖 44）+ 超长 cue 拆分；拆分与质检统一 `cueChars` 口径（此前一边不计空格、一边计空格，同一条字幕一边放行一边判死）。

## 三、动效音效

**上游痛点**：成片完全没有音效；加了音效后，峰值比旁白低 12–21 dB，被完全淹没。

**改动**：本地合成 whoosh / pop / ding 三类音效（`lwb/packs/spoken-video/assets/sfx/`），混音前经 loudnorm 响度归一化，实测混音中清晰可闻。

## 四、配音引擎：云端 MiMo + 本地桥接互斥

**上游痛点**：本地 LongCat 引擎常驻约 23 GB 内存且不释放；渠道默认指向真云端，换个启动方式就报「Invalid API key」，且错误被归咎到音色。

**改动**：
- 接入小米 MiMo 云端 TTS（默认），与本地桥接互斥切换（`ttsProvider: cloud | local`），未选中区置灰。
- 适配 `chat/completions` 形态（文本放 assistant、风格放 user）；有参考音频时自动走 voiceclone 声音复刻。
- 启动时自动探测本机桥接并显示实际地址；认证失败直接指出该改哪里。
- 音色库与配音配置搬进工作台「配音/字幕」页（此前只在桥接独立网页，且无入口链接）：参考音色列表/试听/删除、配音方式、小米音色与语气、数字中文读法。
- 安全边界：API Key 绝不回传（只回 `apiKeyConfigured` 布尔）；音色 id 防路径穿越白名单；保存配置时 apiKey 只在用户真填新值时提交（避免空串清掉已配好的密钥）。
- 引擎控制内嵌：桥接经 `/admin` 端点转发两个引擎的运行状态、显存与内存占用条、一键启动/释放显存/停止、日志尾部与近期任务。实测释放显存使空闲显存 6687 MB → 12721 MB。
- 等待上限按稿件字数上浮：实测 2113 字稿件云端 27 段合成实际跑完却被固定 10 分钟墙钟判死。改为约 100 字/分钟估算 × 1.8 倍余量，下限 10 分钟、上限 45 分钟。

## 五、定时任务：五道闸门 + 排队 + 音色预设 + 自愈

**痛点实测**：2026-10 审计 33 轮定时任务失败 24 轮（73%）。归类后根因高度集中：密钥失效 7 轮、引擎不可达 4 轮（含路径指向已删除的 `E:\ComfyUI-CZX`）、超时误杀 4 轮（2113 字稿件实际跑完、音频已落盘，被固定墙钟判死）、记录被保留上限挤出 + 重启打断 7 轮。而密钥在流水线第 5 个阶段才暴露——前面 20 多分钟已经烧掉。

**五道闸门**：
1. **开工前预检**（`spoken-video-runtime-preflight.mjs`）：体检桥接、引擎、凭据、内存、磁盘；能自愈的先自愈（拉引擎、等 180s、复检），仍不过记 `blocked` 不启动。历史 46% 的失败在第一秒被拦下。预检移入 detached 执行（此前阻塞 30 秒一次的调度器，实测 tick 从 <1s 涨到 3s，整体延后）。内存门槛按「是否真跑本地模型」浮动：云端配音门槛 2 GB（此前被 12 GB 本地模型门槛误拦）。
2. **无进展超时取代墙钟**：观察进展指纹（子任务 updatedAt/阶段），变了就重新计时；纹丝不动超过预算才判死，另设硬性上限兜底。
3. **错误分类驱动自动修复**（`spoken-video-failure.mjs`）：`classifyFailure()` 归 13 类，明确 retryable / autoRepair / remedy；可重试的修复后重入本阶段（不从头）；单设 `code.defect` 类把代码 bug 和环境问题分开。失败处置话术改成可执行步骤（引擎挂时不再引导用户打开一个本身就打不开的页面）。voiceover/subtitles/video 阶段重试 2→4 次。
4. **断点续跑**：重启把在飞轮次标 `interrupted`（原来一律 `failed` 且注释明写 "none can resume"），保留全部产物/引用/阶段轨迹，重启后自动从断点接上；每阶段用 refId 复查子任务真实终态；resume 按 `resumeRunId` 去重、只挡 waiting/active（修掉一条历史 done 续跑条目把同计划后续所有续跑永久挡死的饿死问题）；resumeCount 封顶 3 次。
5. **可诊断性**：`failures.json` 聚类（分类 + 完整错误 + 修法，按签名折叠），界面直接回答「最近为什么失败、该改什么」。

**多任务排队**（`spoken-video-queue.mjs`）：同一分钟到期的多个任务此前互相抢跑，抢输的被 `SPOKEN_VIDEO_SCHEDULE_BUSY` 抛掉且调用点 `.catch(() => {})` 吞掉——用户只看到「今天的任务没跑」。现在全部入队、串行执行、位次可见。一次只跑一轮是刻意的：渲染会打满机器，交错执行的失败在审计里没法读。

**依赖自愈四层**（2026-10-15）：轮次内等外部依赖恢复（`DEPENDENCY_WAIT_MS=15min`）——桥接/引擎掉了先自动拉起续跑，不再立即判死。

**音色预设与渠道跟随**（2026-09-30）：
- 调度轮的配音/字幕请求显式传 `connection.provider`，与「配音/字幕」页手动任务同源（此前归一化把配音硬编码到百炼，连接切到桥接时定时轮仍打百炼）。
- 任务表单支持音色预设：系统默认 / 上传参考音频（≤20 MiB，MP3/WAV/M4A/OGG，逐轮落到项目 `audio-media/references`，重试幂等）/ 桥接内置音色（云端）/ 桥接音色库；语速、音量、预期风格按任务覆盖。
- `stageScheduleVoiceReference` 改为 `(agent, request)` 风格，与 media-host 其余公开方法入参约定对齐。

**提示音与通知**：浏览器端 WebAudio 实时合成提示音（完成 660→880 上行双音，失败 440→220→120 下行加低频脉冲），0 字节资源；`alerts.json` + 独立计划任务 LWBAlert 每分钟播报，不依赖浏览器；页面内弹窗只在「本页开着时刚发生」的终态出现（结束时间晚于本页首次取数时刻），失败弹窗优先显示 remedy。

## 六、审片与内容安全

- `settings.yaml` 声明模型 `input: [text, image]`，解除 `read_image` 拒绝——此前审片 Agent 三轮必然失败。
- 解开「审片要求实拍 vs 创作禁用素材」的提示词自相矛盾。
- 审片抽帧：随场景数增长（旧上限 8 帧会让多场景成片落库直接失败），按场景中点抽帧；修掉 `parseSceneSpans` re-export 导致的 ReferenceError 被 `.catch(()=>[])` 吞掉、场景对齐抽帧自实现起从未生效的问题；读取失败重试 3 次并写可见 run event「审片抽帧退回盲选」，降级不再无声。
- 叙事节奏判据进 Agent：幕长/句密度判据来自 46 条历史成片实测分布（`spoken-video-rhythm.mjs`），不设硬幕长；运动词汇表（Wise Motion）写入视觉导演提示词。
- 新增内容安全扫描（`spoken-video-content-safety.mjs`）与场景 cue 覆盖核对（`spoken-video-scene-cues.mjs`），并入预检。
- 灾难性回溯修复：`stripHookAnnotation` 的 `(?:[\s\S]{0,2})*` 前缀正则在「正文不带标注」时穷举切分方式，几千字稿件冻结事件循环数小时（端口在、HTTP 死、CPU 单核满）。重写为线性扫描，2.8 万字 0.16ms，含性能回归锁。
- `structured` 生成补一次同会话 followup 要求补交（模型偶发回短文本就结束 turn、不调 structured_output，此前零重试且无 diagnostic）。

## 七、封面生图

- **标题改由 AI 直接绘制**（2026-10-09）：实测本机 Qwen-Image（20B）写汉字完全正确、零乱码。旧的「底图留空 + 程序叠字」产出「正确但没人会点」的封面。现在标题当视觉主体写；程序侧退为质检：`inspectCoverTitleZone` 边缘检测判断 AI 是否写了标题，阈值 18 来自四张真实封面的实测能量分布（艺术字 28–30、工整白字 9.8、纯底图 7.7）；低于阈值只记事件提示重生，不阻断。
- **提示词简化为固定句式**（2026-10-10）：十条硬性规则改为一句固定前缀 + 主题（在 `normalizePublishResult` 里强制套用）；`shortenCoverTitle` 挑句而非硬砍（打分按带数字与结果词，不按长度）；手改的提示词不被「重新生成发布信息」覆盖（判据必须比本轮句式）。
- **自定义云端生图渠道**（2026-10-10）：custom 成为一等渠道，支持 `openai`（/images/generations）与 `async-generic`（提交+轮询）两种协议；尺寸写法区分（百炼 `1280*720`、OpenAI `1280x720`）；b64_json 转 data URL 独立解码分支；地址校验拒绝带查询串/账号密码的地址（防凭据泄漏）；配置随任务冻结；密钥可留空。
- **错误分类三分支**（2026-10-10）：超时/断连 → 保留「可能已计费，请先到服务商后台确认，不要重复提交」；服务端明确拒绝（4xx，如模型名不存在）→ 原样抛出真实原因，不套「不可访问」；其余按不可访问。此前参数被拒被误报成「不可访问」，人去查网络而不查模型名。
- **同步端点 300 秒超时**（异步提交 60 秒），此前 fetch 无限期挂住。
- **「缺少服务地址」回落 `customImageDefaults` 预设**（2026-10-15）：四处判定统一回落，不再误伤从没打开过表单的用户。
- **封面生图引擎空闲自动回收**（2026-10-10）：实测 8187 生图引擎（Qwen-Image）占 5.8 GB 内存 + 14016/16376 MB 显存，而封面 40/40 全走云端百炼，本地引擎不在工作台链路里。改为两级回收：空闲 5 分钟 → `/free` 卸模型还显存；空闲 20 分钟 → 停进程还内存。到期先查 ComfyUI `/queue`，在跑就重新计时。实测（阈值 30s/60s）：空闲内存 5.2 GB → 21.4 GB、显存空闲 2.5 GB → 8.2 GB；新任务自动拉起成功。
- 竖封面槽位修复（2026-10-11）：横竖封面是两个独立方块（实测竖封面仅 90 宽，被 `width > 100` 过滤筛掉），按 class 前缀 + 坐标去重定位，坐标必须动手前一次性量好。

## 八、发布器（发布与账号管理包）

- **抖音适配器按实机截图与真机探针校准**（2026-10-11 三轮）：标题上限 55 → 30（输入框角标 `0/30` 实测，常量导出 + 回归测试锁住）；等上传真正完成再填字段（按已上传字节数判，页面在 97% 时写的是「已上传：29.4MB/29.9MB」无百分号）；封面两段式（点「选择封面」开弹窗 → 先挂 filechooser 监听 → 点弹窗内上传按钮）；自主声明选完点「确定」关模态（否则遮罩一直盖在页面上）；封面比例容差 ±0.45（实测 16:9 与 1088×1440 平台都照收）；「文字显示不全」提示画在缩略图上不在 DOM 里（实测遍历 180 万字符 innerHTML 得 nodeCount=0），任何页面文本判据抓不到，属于封面生图层。
- **视频号助手适配器**（2026-10-15）：登录判定/编辑器跳转/竖横封面顺序按真机探针实测；选择器全部是优先级列表，平台改版退化为截图报错而非点错。
- 发布记录含 title-truncated / description-truncated 阶段；截断按码点切（emoji 在 `.length` 里算两个单位）；上限可通过 `content.titleLimit / descriptionLimit` 覆盖。
- 每条成片都是脚本 + 合成配音 + AI 封面，自主声明默认「内容由AI生成」；自动模式选不出就报错，绝不静默发一个声明缺失的作品。
- 发布包装 prompt 补互动引导规则（描述区征集问题、禁空话、禁剧透）。

## 九、可观测性与 UI

- 视频制作：步骤条 + 实时计时 + 失败原因 + 可展开执行明细；补齐 editorial-repair 阶段中文标签。
- 媒体桥接控制台：两栏布局 + 1200px 内容约束 + 任务过滤、保留上限 500→100、清空已结束、运行日志面板。
- interrupted / blocked 终态接进状态筛选器与任务卡色标（橙色 = 等它自己接上，红色 = 去改配置）。
- 选题页 → 写稿页带项目交接；配音页三面板栅格重排。
- 民间故事账号优化（2026-10-15）：4 个故事赛道钩子触发器 + 说书人写稿结构 + 钩子标注防泄漏（prompt 禁令 + `stripHookAnnotation` 防御剥离，只剥开头）。

## 十一、稳定性（Windows 生产环境）

- **原子写入 EPERM/EBUSY 退避重试**：Windows 下 rename 被轮询读句柄阻塞，选题任务实测 11 次失败 7 次。6 处原子写入加退避重试。
- **TEMP/TMP 重定向出系统盘**：渲染暂存目录运行期按可用空间自动选盘（非系统盘中可用空间最大且 ≥ 20G 者，无则退回系统盘 LOCALAPPDATA；`LWB_SCRATCH_ROOT` 可钉住）。Node 侧与「设置渲染暂存盘.ps1」用同一套选盘逻辑——两边不一致时表现为「等了 40 秒还是没打开」。一并设置 HF_HOME/TORCH_HOME/npm_config_cache 与 HF_ENDPOINT 镜像（huggingface.co 国内直连超时实测）。
- **路径比较大小写不敏感**：修复能力包侧边栏空白。
- **npm/pnpm 走 JS 入口**：Windows 下 Node 24 拒绝无 shell 地 spawn `.cmd`（CVE-2024-27980），直接 spawn 得到退出码 null。改为直接跑 `npm-cli.js` 与 `corepack.js`。
- **正则冻结修复**（见第六节）。
- **队列 resume 饿死修复**（见第五节）。
- **字幕拆分与质检字数口径统一**（见第二节）。
- 首次运行设 `CI=true`：pnpm 无 TTY 时不敢清空 node_modules（`ERR_PNPM_ABORTED_REMOVE_MODULES_DIR_NO_TTY`）。

## 十二、Windows 启动与交付链路

- **交付包构建**（`scripts/build-delivery.mjs`）：源码从 `git archive` 取（工作副本的 junction/hardlink 复制必败，实测 66027 文件里几百个符号链接失败）；归档后 `git init` 单提交满足 DSH 构建脚本的 `git rev-parse HEAD`；依赖现场安装（npm ci 7s / pnpm install 17s，走 npmmirror）；拒绝脏工作区；渲染浏览器打进包（实测快 5.6 倍：11073 帧 20 分钟 → 3.5 分钟）；标准版不含桥接目录。
- **压缩**：走 Python zipfile（Compress-Archive 按 ANSI 编码写条目名，中文文件名实测变乱码）；跳过 junction（`st_file_attributes & FILE_ATTRIBUTE_REPARSE_POINT` 判定；`os.path.islink` 对 Windows junction 返回 False）；pnpm workspace 链接必须保留（误删后 vendor 报 `ERR_MODULE_NOT_FOUND: @deepseek-ai/cordis`）；zip 存不了链接 → 「全跳过 + 客户机 `首次运行.cmd` 重建」（pnpm 重建 25 秒）。
- **解包**：System32 原生 bsdtar（Git Bash 的 tar 把 `F:` 当远程主机报 "Cannot connect to F:"）；归档路径避开 MSYS 盘符改写；导出改用 `git worktree`（原生 tar 中文文件名报 Invalid empty pathname）。
- **随包携带 Node 与 FFmpeg**：客户机没装 Node 时双击第一个脚本就报 `'node' 不是内部或外部命令`。包内「运行环境/」放 Node（约 105M）与 ffmpeg+ffprobe（约 197M），四个入口脚本都把随包运行时放 PATH 最前面，系统安装作后备。
- **启动流程**（`启动工作台.cmd`）：随包运行时置前 → 选渲染暂存盘 → 4173 已应答则拒绝二次启动（EADDRINUSE 看起来像启动失败）→ 桥接 8199 未应答且目录存在则拉起 → 渲染浏览器优先用包内 `浏览器\chrome-headless-shell-win64\`（MAX_PATH 260 限制，必须短路径）→ 带鉴权 token 的访问地址 tee 到 `workbench-url.txt`（ASCII 写入，UTF-8 BOM 会粘坏 URL 首字符，实测「?ttp://...」）。
- **保活与告警**（`ops/`）：`lwb-keepalive.ps1` 与 `lwb-alert.ps1` 纳入版本控制；路径解析四级查找（环境变量 → 同目录 lwb-repo.txt → 脚本位置向上找 → 逐盘符桌面下找），最后一步必须验证 `media-bridge/` 真实存在（`$env:USERPROFILE` 推测桌面实测拼出不存在的路径）；编码规则：`.ps1` 要 UTF-8 with BOM、`lwb-repo.txt` 读取要 `-Encoding UTF8`、wscript 启动器要 GBK 无 BOM（VBScript 不支持带 BOM 的 UTF-8）；保活分支新增 Test-ScheduleBusy（有 running/interrupted 轮次时不重启，避免打断 20 分钟流水线）；工作台拉起后 15 秒确认，失败写告警；LWBKeepAlive 补 RestartOnFailure。2026-10-17 修复 interrupted 死锁（interrupted 的恢复前提恰是工作台在线）与拉起路径硬拼桌面（10-09 起 15 次拉起静默失败）；启动脚本 mkdir 误把 token 文件路径建成目录已修。
- **媒体桥接入库**（2026-10-10）：约 2500 行桥接源码从仓库外搬入 `media-bridge/` 成为唯一真源；`config.json`（含密钥）、`data/`、`voices/` 被 `.gitignore` 挡住（构造场景验证过：敏感文件就位时 git 仍只收 6 个源码文件）；缺 `config.example.json` 直接构建失败（此前 existsSync 静默跳过，交付包缺件无人知）；「交付模板不得含密钥」有测试断言；`saveConfig` 剥掉 `$` 前缀注释键。

## 十三、能力包与仓库基础设施

- 补齐 publisher 与 whiteboard 包入库（此前 package.json 的 unit:test 写着它们的测试路径而 git 里不存在，克隆下来 `npm test` 直接失败）；`.gitignore` 补 `**/.venv/`（白板引擎 Python 虚拟环境 252M / 1952 文件）；`prepare_env.py` 走清华 pip 镜像（官方源装 opencv-python 国内实测 35 分钟未完成），`LWB_PIP_INDEX_URL` 可覆盖。
- 干净克隆修复：`linkInRepoPacks()` 为 `lwb/packs/` 下所有包补建依赖链接并接到 `npm test` 前置（包的 peerDependencies 是 `workspace:*`，只在包被 UI 加载时建链，测试直接 import 会失败）；建链前先确认 vendor 已构建（existsSync 对指向空目标的 junction 仍返回 true，会掩盖「缺上游」根因）。
- 浏览器路径支持三种形态（exe 本身 / win64 目录 / 上级目录）；渲染浏览器三级回退（环境变量 → `node_modules/.remotion` 共享目录 → 系统浏览器）。
- 自检脚本重写（Python 字符串替换把路径里的 `\a`、`\n` 吃成转义序列，整个文件语法崩掉）；依赖链接判据改为实跑 `pack:link`（幂等 0.1 秒；路径探测在首次运行成功后仍误报）；自检输出「配置建议书」而非「体检表」（按实测门槛分四档：8G 卡只能做字幕；本地配音真门槛是 23G 内存不是显存）。
- `unit:test` 从逐文件列举改为 glob 发现（此前新写的测试文件不会被自动发现，一条桥接测试一直 `t.skip` 无人察觉）。

## 升级边界

1. **不修改 `vendor/deepseek-harness`**。所有增强通过包装、补丁配置（`lwb/dsh-bundle/cordis.patch.yml`）与独立模块落在 `lwb/` 层。升级上游 DSH 时只需重新 `npm run setup`，本地增强理论无冲突，但上游行为变化可能需要重新验证（上游锁定 `dsh-v0.1.6-alpha.1`）。
2. **media-bridge 是独立进程**，不在工作台进程内。标准版交付包不含桥接目录；本地增强版才带。桥接的引擎（封面生图 ComfyUI、字幕引擎）依赖独立安装，见交付包「引擎安装指引」。
3. **实测数据与特定硬件/平台绑定**。显存/内存数字来自本机（RTX 显卡 + Windows）；抖音/视频号适配器的选择器来自 2026-10 真机探针，平台改版会退化（适配器设计为「退化为截图报错而非点错」，不会发错内容，但需要重新校准）。
4. **平台规则常量可覆盖**。抖音标题/描述上限做成 `content.titleLimit / descriptionLimit` 可覆盖——平台会调整它而本机没有联网通道能核实当前值，凭记忆写死错起来比不写更糟。
5. **定时任务一次只跑一轮**是刻意设计（渲染打满机器、审计可读性），不是缺陷。
6. **测试口径**：单测数量随包增补，以 `npm run unit:test` 实际输出为准（截至本文撰写包含口播、发布器、白板、对标拆解、情感故事号等包的测试）。涉及真机发布的测试依赖真实浏览器与平台页面，日常由适配器内的回归断言（几何常量、上限常量）守住。
