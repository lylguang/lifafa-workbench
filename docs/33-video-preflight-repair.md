# 视频工程预检与修复

> 历史设计/验收记录，包含当时的方案与限制，不作为当前使用指南。当前入口见[文档索引](README.md)和[快速开始](quickstart.md)。

2026-09-16

原预检只用正则匹配 `animation:` / `transition:`，把 `transition: "none"` 也当成不可确定渲染的动画。改为解析 TSX 语法树及内嵌 CSS 声明，放行显式 `none`（含 TypeScript 类型断言），忽略注释和普通说明字符串；实际动画、无法确认关闭的动态值仍被拒绝。错误记录包含文件、行列、属性和值。该静态检查不是对任意 JavaScript 的完整确定性证明，后续仍须实际渲染和质检。

`spoken-video-preflight.mjs` 是主流程与 Agent 共用的检查器。新任务把它复制为 `scripts/preflight.mjs`，生成受保护文件摘要清单，在 `task.json.commands.check` 公布本地命令。Agent 必须调用这条命令，而非自行写正则检查；主流程再次用可信检查器和内存中的文件摘要验证产物，检查器和清单本身也受保护。

视频创作结束后，主流程先检查工程。如果问题可修正，执行器保留现有子会话，在原会话中发送带具体错误位置的修复要求，最多修复两轮。每轮都重新检查，过程记录包含次数和诊断。达到上限仍失败、执行中断或受保护文件被修改时，不进入渲染，也不提交视频产物。取消信号同样覆盖后续修复轮次。独立审片的失败策略不变。

新任务的 `node_modules` 是本地目录，各依赖和已安装的 Remotion 浏览器通过单独链接复用；`node_modules/.cache` 留在任务目录内。这样 Webpack 缓存清理和写入不会穿过旧的整个 `node_modules` 软链接，触及项目根目录缓存。检查命令直接使用本地 Node 和 Remotion，不调用 `npx` 下载工具。旧工程的依赖目录可通过 `ensureAgentDependencies` 迁移，该过程仅替换任务自身的依赖链接。
